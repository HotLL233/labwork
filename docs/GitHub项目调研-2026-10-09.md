# GitHub 项目调研：理化录入、计算与原 Excel 回写

日期：2026-10-09，北京时间。检索覆盖 LIMS、laboratory information management、chemistry LIMS、中文检测相关仓库及通用数据平台。核查了仓库元数据、README、相关安装/迁移说明和许可文件；没有部署运行候选系统。

## 1. 结论

有可参考的检测管理系统，也有可搭建平台的开源框架，但本次未找到经验证能够即装即用地接管现有工作簿并安全回写原表的项目。

针对“内网多人在平台录入计算，再写到现有表格”的需求：优先参考 SENAITE 的业务组织；采用轻量 Django 应用实现受控方法与回写。若团队已有 Frappe 经验，可选 Frappe 自定义应用。无论采用哪条路线，原表映射与回写均要自行验证。

## 3. 最值得看的三个方向

### SENAITE：检测流程参考

[核心 README](https://github.com/senaite/senaite.core/blob/2.x/README.rst) 说明其为企业环境 LIMS，基于 Plone，核心包由 SENAITE.LIMS 使用；不应把 core 单独当完整系统安装。[IMPRESS README](https://github.com/senaite/senaite.impress#usage) 明确展示样品验证后生成、预览和保存 PDF 报告及选择模板的流程。

检查到的 [2.x Installation.md](https://github.com/senaite/senaite.core/blob/2.x/Installation.md) 仍要求 Python 2.7。[P8 迁移文档](https://github.com/senaite/senaite.core/blob/2.x/P8_UPGRADE_GUIDE.md) 说明 Python 3/Plone 升级路线。API 返回的最新发布为 core `v2.6.0`，发布时间为 2025-04；这与近期源码推送应分开看。

因此，本次把它列为业务参考优先，而非默认推荐直接 fork 的现代 Python 底座。若要部署，应先核定目前受支持的发行版、镜像、依赖和升级路线。上述文档可能存在历史内容，不据此断言所有分支或商业发行版都采用同一运行环境。

可借鉴：检测项与方法区分、样品到检测记录的关系、验证与报告模板。当前原 Excel 文件的行列映射与写入仍需另开发。GPL 代码若要复制或分发须遵循相应许可，参考业务概念与直接复制代码不同。

### Frappe：快速搭建受控表单的底座

[README 功能](https://github.com/frappe/frappe#key-features) 列出内置后台、角色权限、REST API、可配置表单和报表构建；[LICENSE](https://github.com/frappe/frappe/blob/develop/LICENSE) 为 MIT。README 描述 Python + MariaDB 的服务端架构，并给出 Docker/Bench 部署方式。

适合把项目、样品、方法、检测记录定义成受控单据，避免重写表单和权限。代价是学习 Frappe 元数据和部署生态；不是把原 Excel 上传后就自动获得全部公式和回写的系统。采用它时应按其受支持数据库和部署方式执行，不能照搬 Django 路线的 PostgreSQL 配置而不核实。

ERPNext 是 GPL-3.0 的完整 ERP，许可与 Frappe 框架不同。如果只做理化录入/回写，不需要先引入整个 ERPNext。

### eLabFTW：实验记录归档

[README](https://github.com/elabftw/elabftw#features) 明确包含实验记录、资源数据库、导入导出、权限、REST API 和多团队使用；支持 Docker 自部署。适合把原始文件、备注和实验依据集中归档。

本次没有查到 README 证实其直接支持当前理化算法及指定原工作簿的定点回写。若选它，仍需计算和回写适配；当前核心需求下，未必比轻量应用更短。

## 4. 中文仓库和 NocoDB 的具体边界

[2387452986/lims README](https://github.com/2387452986/lims#许可) 写明公开用于技术作品展示，未附开源许可证，默认保留全部权利，不主动授予复制、修改、再发布或商用许可。[NOTICE.md](https://github.com/2387452986/lims/blob/main/NOTICE.md) 再次确认没有为原始应用代码授予开源许可。业务描述全面，不等于可以合法直接复用；README 也声明其是 `0.1.0-SNAPSHOT` 技术展示，不能把描述当成已完成机构生产验收。

ChemistryLIMS 的 README 描述基于 Django，根目录确有 sample、method、product、equipment 等模块；但维护停留在 2021 年，且未见许可证。不作为可直接复用的推荐。

[NocoDB 当前 LICENSE.md](https://github.com/nocodb/nocodb/blob/develop/LICENSE.md) 是 Sustainable Use License，文件标注更新于 2026-01-29。条款允许自身内部业务或非商业/个人使用，向他人分发/提供另有免费非商业限制。不能按过去印象把当前版本标为 AGPL 或 MIT。内部台账试用可评估，但产品化或对外分发需按实际许可核定。

## 5. 推荐如何组合参考

| 当前需要 | 参考/复用来源 | 本项目仍需完成 |
| --- | --- | --- |
| 账号、权限、校验、事务、后台 | Django 原生能力；Frappe 为备选底座 | 项目数据范围、检测人员操作界面 |
| 检测业务结构 | SENAITE；中文 LIMS 的公开业务说明 | 针对当前项目和方法的精简数据模型 |
| 原始记录与附件 | eLabFTW 的归档方式 | 来源追溯、文件备份与核定记录 |
| 当前理化计算 | 现有工作簿 + 经业务核定的方法 | 参数差异确认、明确算法、单位、平行测定与舍入验证 |
| 原 Excel 回写 | 本次未找到经验证的直接匹配方案 | 原表映射、局部更新、幂等、占用/冲突与兼容性验收 |
| 正式报告，若以后需要 | SENAITE IMPRESS 的模板与预览设计 | 实验室正式模板、签发权限与报告版本 |

当前推荐先用 D006 与 Q 的副本验证“录入—计算—回写—重新打开核对”。原表兼容性通过后，再扩展到全部项目。完整实施范围见 [平台方案 v1](理化检测平台方案-v1.md)。
