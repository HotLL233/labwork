# 理化检测平台方案 v3：Rust、SQLite 与原表录入

日期：2026-10-09。已确认：单台服务器、实验室局域网、多用户浏览器访问；Rust + SQLite；按项目和检测方法还原原表，支持单元格录入、键盘切换、计算和写入预览，适配手机。

## 1. 安装包缩小的依据

当前 Windows r2 安装包约 92.6 MiB。解压后的业务代码约 3.7 MiB，Python 环境约 109 MiB，PostgreSQL 约 134.6 MiB，另含 HTTPS 网关和服务管理器。单纯把 Python 改成 Rust、继续附带 PostgreSQL，仍会保留较大的数据库组件。

新版采用 Rust 服务端、内嵌 SQLite、随可执行文件编入的 HTML/CSS/JavaScript。移除 Python 和独立 PostgreSQL 服务。正式版计划使用 Rust TLS 和 Windows Service API，进一步移除 Caddy、WinSW；仍为后台网页服务，不做独立客户端 App。

已建立 `rust-preview` 验证程序，真实完成 SQLite 持久化、14 方法计算、OOXML 读取、原表样式预览、生成 XLSX 副本、确认追加、备份、幂等和冲突检查。第一次 release 构建为 2,452,480 字节；静态 CRT 构建和最终包大小另见验证记录。该数字只代表验证程序，不能当作完整平台安装包的承诺。正式完整安装包暂设 15 MiB 以内为目标，完成账号、TLS、服务安装与依赖检查后以实际构建为准。

## 2. 项目、方法与页面

访问顺序：项目 → 方法 → 原始数据 → 计算 → 写入预览 → 确认写入 → 同步状态。

桌面页沿用熟悉的表格操作：项目栏、方法页签、命令区、单元格地址框、公式栏、行列编号、原表区域和工作表页签。按真实模板读取字体、字号、颜色、边框、对齐、数字格式、列宽、行高和合并范围。已有记录展示为只读，本次录入区域以浅黄色区分，计算后的拟新增行以绿色标记。点击单元格可查看原值和公式。

编辑字段从项目、方法和已核定映射生成，不能让用户随意覆盖历史行或计算单元格。支持 Tab/Shift+Tab、Enter、方向键和从 Excel 复制矩形数据粘贴；超出字段或平行测定范围时明确拒绝。首期仍为一至两次平行测定。取消预览不改工作文件，重新录入会使旧预览失效。

手机页使用同一份数据和同一 Rust 计算接口，字段按方法显示为触控录入卡片，保留单位和错误信息；结果放在录入区下方。原表视图保留横向滚动，不把整张宽表强行缩小。桌面、手机视图切换不丢输入，均能预览、确认写入和下载副本。

用户已选择方法级还原，本期不做通用 Excel 引擎。宏、VBA、任意新公式、自由插删行列、拖动历史单元格及全部 Office 绘图交互不属于已确认范围；原工作簿中未修改的部件保留。遇到图片、按钮、复杂条件格式、共享公式、打印布局等特征，须逐模板增加渲染或保留检查，不能宣称所有 Excel 功能已完整复刻。

## 3. 计算、预览与回写

Rust 使用十进制计算，沿用旧版输入校验、单位、空白修正、稀释换算和展示精度，禁止用浏览器浮点结果代替服务端结果。每次记录保留原始输入、输出、方法版本、参数和映射快照。

预览接口完成服务端计算，并生成实际候选 XLSX。页面渲染这份候选文件；下载预览和最终写入使用同一份候选文件及其指纹，避免“页面算一遍、写表再算一遍”。预览阶段不替换工作文件。

确认写入采用单一串行写入者：核对预览令牌、权限、方法核定状态、工作簿指纹、表头和目标区域；写前备份；持久记录写入意图；同目录原子替换；回读确认；记录写入状态。重复确认不重复追加。外部修改导致冲突，Excel/WPS 占用时保留记录并允许重试。中断后用前后指纹判断是否已经替换，而非再次盲目追加。修订继续追加新记录并关联旧记录。

XLSX 继续局部修改已纳管的工作表 XML，其他 ZIP 部件保留。新增结果同时写入经过核定的公式和缓存值。未知联动公式、合并区域或未经识别的模板不能自动写入。

## 4. SQLite 与多人使用

SQLite 数据库只放在服务器本地磁盘，由 Rust 服务访问；客户端通过 HTTP API，不能把 `.sqlite3` 放在网盘/SMB 上供多台电脑直接打开。启用 WAL、外键、合理 busy timeout 和事务。文件回写串行，网页读请求可并发。

正式模型保留用户、项目授权、方法及版本、工作簿及映射、记录及测定明细、回写任务、复核和审计。管理员、检测、复核、只读权限在每个接口校验，复核人员不能复核本人记录。密码散列、会话过期、CSRF、来源限制、登录限流继续保留；不能用“内网”代替账号权限。

当前验证版只实现预览记录与方法快照，固定绑定 `127.0.0.1:18802`，采用本机防跨站令牌和 Host 校验；尚未迁移用户权限，因此禁止直接改为局域网监听或替代正式系统。正式版内网开放需在权限迁移和 HTTPS 验证后完成。

备份必须同时覆盖数据库、工作簿和相应任务状态；在线数据库采用 SQLite backup API，不能只复制正在使用的主数据库文件而漏掉 WAL。恢复先在隔离环境核对记录、任务与文件指纹。

## 5. 版本与部署隔离

| 对象 | 地址或路径 |
| --- | --- |
| 现有正式平台 | `https://172.28.10.177:8443`，服务 `Labwork`，数据 `C:\ProgramData\Labwork` |
| Rust 开发分支 | `feature/rust-excel` |
| Rust 工作区 | `C:\labwork\.worktrees\rust-excel` |
| 当前验证页面 | `http://127.0.0.1:18802`，只供本机 |
| 当前验证数据 | 工作区 `runtime\rust-preview`，独立 SQLite 与工作簿副本 |
| 候选正式 Rust 部署 | 程序 `C:\APP\LabworkRust\releases\0.0.2`，数据 `C:\ProgramData\LabworkRust`，服务 `LabworkRust`，独立 HTTPS 8444 |
| 验证发布目录 | `C:\labwork\releases\v0.0.2-alpha.1` |

v0.0.1 与 Windows r1/r2 标签及包保持不变。开发和验证不读取现有数据库凭据，不停止现有正式服务，不写网盘原件。

正式切换前，只读导出旧 PostgreSQL 的账号、授权、方法版本、记录、任务、审计和工作簿登记；在新目录导入 SQLite 并校验数量、关系、散列、状态和文件指纹。用户密码需验证原散列兼容性，不能悄悄替换密码。记录 ID 和修订关联保持可追溯。

切换时停止旧系统的新提交和正式回写，完成一致性备份与差异核对，再启用新系统的唯一正式写入者。测试期间两个版本可同时运行，但只写各自副本。

首次试运行可直接回到旧版本，因为没有修改旧数据。正式 Rust 版产生新记录后，不能简单启动旧 PostgreSQL 版本并宣称无损回退；需停写、导出新记录并做已验证的回迁/对账。以后 Rust 版本之间优先按 SQLite schema 兼容性回退代码，保留业务数据。

## 6. 实施与验收

1. **技术与界面验证**：Rust + SQLite 核心、D006/Q 的 14 方法、真实原表副本、桌面/手机视图、预览与确认追加；测量二进制和包体积。当前阶段。
2. **业务迁移**：账号和项目授权、草稿/提交、筛选、复核、追加修订、方法核定、上传/下载、回写重试与审计；迁移旧版回归用例。用户要求继续开发此阶段。
3. **服务与包装**：Rust 内网 HTTPS、Windows 原生服务、自启动与正常停止、中文 Inno 安装器、独立数据目录和版本路径；单一 Rust 镜像加持久卷的 Docker 包。安装器明确区分“监听网卡”和“浏览器服务器地址”，拒绝 `0.0.0.0` 作为访问地址。
4. **切换验收**：旧数据只读导出/导入对账、多人并发、占用/冲突/中断恢复、备份恢复、Excel/WPS 副本重算及手机实际设备操作，完成后才能发布正式 v0.0.2。

验收重点：两版计算在核定精度内一致；预览与写入行一致；无关部件和原件保持；重复提交不重复写；权限和复核不能绕过；数据切换及回退不造成记录丢失。安装包大小以实际含完整功能的产物为准。
