# 理化检测平台方案 v2

更新日期：2026-10-09。项目目录：`C:\labwork`。

本版按已确认需求收敛：**局域网多人使用浏览器，在平台录入和计算，写回现有 Excel；支持 Excel/WPS 核对；开发和正式运行需要版本隔离。** 使用端只提供网页，服务端集中运行。

与 v1 相比，本版明确项目位置、代码和运行环境隔离、局域网部署、浏览器端文件访问，以及发布和回退规则。原始表格分析仍采用 [工作簿功能清单](工作簿功能清单.csv)、[v1 来源与问题实例](理化检测平台方案-v1.md) 和 [GitHub 调研](GitHub项目调研-2026-10-09.md)，避免重复维护调研结论。

## 1. 最终产品与技术选择

产品是一套内网网站。实验室电脑访问统一网址，登录后选择项目、样品和检测项，录入原始数据、查看计算结果、提交写表并查询同步状态。日常使用不依赖客户端电脑安装 Python、数据库或办公软件；需要查看原 Excel 时，可从平台下载，用 Excel 或 WPS 打开。

固定采用 **Django + 服务端 HTML 页面 + PostgreSQL + 单个串行回写进程**。账号、表单、校验、权限和事务复用 Django，少量 JavaScript 支持行录入和计算结果刷新。计算以服务端为准，浏览器不能提交一个结果就跳过原始数据和方法校验。

SENAITE 作为检测业务参考，Frappe/eLabFTW 等保留在调研资料中。当前不继续搭建多个框架试验项目，也不引入完整在线 Excel 编辑器。原表回写的兼容性是优先验证项。

服务端的回写进程属于同一项目内部任务，用户只看到网站。首期不拆前后端，不采用微服务、Redis、Celery、Electron 或桌面安装包。

### 2.3 数据与写入范围隔离

| 环境 | 代码位置 | 数据库示例 | Excel 范围 | 回写规则 |
| --- | --- | --- | --- | --- |
| 开发 | 对应功能 worktree | `labwork_dev_<任务>` | `runtime\dev\<任务>\workbooks` 中的副本 | 默认关闭；回写实验只对副本显式启用 |
| 测试 | 测试 worktree 或候选发布副本 | `labwork_test` | `runtime\test\workbooks` 中的验收副本 | 可回写副本，不能连接正式库或写原表 |
| 正式 | `releases\<固定版本>` | `labwork_prod` | 经登记和核定的正式文件 | 专用账号、明确文件白名单、单一回写进程 |

每个环境各自保存配置、账号、数据库、日志和文件备份，环境配置不进入 Git。并行开发工作区也不共用同一开发数据库。正式数据库迁移只能由发布步骤执行，开发启动不自动操作正式库。

程序启动校验环境标识、数据库目标与 Excel 路径白名单；开发/测试的回写目录不得指向正式原表。进一步通过独立数据库账号和 Windows 文件权限限制测试服务账号，不能只靠配置文字约定。密钥、业务工作簿、数据库文件和真实附件均不纳入 Git。

方法版本、试剂标定版本、模板映射版本与应用发布版本分别记录。更新程序不能自动改变历史方法或用最新浓度重算已提交记录。

## 3. 局域网部署与文件访问

### 3.1 一个服务节点

优先选一台常开 Windows 主机，集中运行网页服务、PostgreSQL 和回写进程，便于访问当前 Windows 文件路径。无需先购买服务器或拆成多个节点；若已有服务器，则选择能稳定访问目标文件的现有节点。

```mermaid
flowchart LR
    U[实验室浏览器] --> H[内网 HTTPS 入口]
    H --> W[Django 网页服务]
    W --> D[(PostgreSQL)]
    D --> J[串行回写进程]
    J --> X[登记的 Excel 工作簿]
    J --> B[回写备份与日志]
```

内网网址使用固定主机地址和名称，例如 `https://labwork`；这是待配置的示例，不是已经开通的地址。通过 DHCP 地址保留或固定 IP 保证入口稳定，名称由内网 DNS 或统一 hosts 配置解析。

Windows 正式网页进程使用 Waitress 等受支持的 WSGI 服务，不能用 Django `runserver` 承担正式运行。优先复用已有 HTTPS 入口；没有时增加一个 Caddy 入口，采用实验室客户端可验证的内部证书。浏览器仍正常验证证书，内部 CA 由管理端统一配置一次。

PostgreSQL 和网页内部端口只对本机开放，实验室客户端通过 HTTPS 入口访问。防火墙仅允许指定局域网范围，首期不配置公网映射。服务和回写进程由系统服务管理自动启动；可复用现有服务管理方式，Windows 任务计划用于日志轮转、定时备份等固定任务。正式服务不依赖有人登录并打开终端窗口。

主机休眠或关机会中断访问和回写，因此工作时段要保持运行；工作簿暂时不可访问时任务留在队列，恢复后按规则重试。

### 3.2 文件在服务器处理

- 浏览器提交检测数据，服务器通过已登记映射选择目标文件。用户不向服务器传任意绝对路径。
- 客户端电脑的 `C:\...` 与服务器的 `C:\...` 不代表同一文件。网页通过带权限校验的预览/下载接口提供源表，不靠网页链接让其他电脑直接打开服务器本地路径。
- 平台录入无需所有人获得网盘或共享文件夹的写权限。正式 Excel 由服务节点回写，其他人以平台查询或下载为主。
- 若目标在其他主机，服务账号使用受控 UNC 路径访问，不能依赖某个用户登录后才出现的映射盘符。
- 指定一份权威的正式工作文件。网盘跨设备双向修改可能覆盖服务器结果；保留当前网盘路径回写前，先核定客户端同步与人工编辑规则。不能建立独占写入时，采用受控工作目录，网盘接收备份/发布副本，并在切换前确认路径映射。

数据库是平台提交记录的主记录，Excel 是与原工作方式兼容的同步台账。下载后的 Excel 副本修改不会自动合并回平台；若确需导入修订，必须经过单独的差异核对流程。

## 4. 首版业务流程与回写规则

### 4.1 用户流程

1. 登录，选择项目、样品和检测方法。
2. 录入质量、体积、温度、稀释等原始数据，或仪器/文字/区间结果。平行测定使用明确的测定序号。
3. 平台显示结果、单位、方法版本和标定参数；缺少必要输入时显示具体缺项。
4. 保存草稿，或点击“提交并写表”。服务器验证后，在一次数据库事务中保存记录和回写任务。
5. 后台回写原表；页面显示“待回写、回写中、已成功、文件占用、冲突、失败”等状态。提供重试和有权限的文件下载。
6. 修订保留旧版本、修改理由、操作者和时间。默认有效提交即可写表；复核权限可先用于核查记录，是否将复核设为回写前置由业务核定。

**保存成功和回写成功必须分别显示。** 文件占用不能导致检测数据丢失，也不能把尚未写入 Excel 的记录显示为已同步。

### 4.2 计算与映射

按“项目 + 检测方法版本 + 模板映射版本”选择字段及公式，不用同名工作表一概套同一个公式。现有 12 个工作簿、137 个工作表的结构已整理；其中的示例行、目录页、空白页及完成登记须分别处理。

先核定 v1 记录的浓度标注与公式系数差异、除零错误、单位、平行分组和舍入规则。使用明确的计算函数及参数快照，避免执行上传表格中的任意公式脚本。服务端保存未舍入结果和最终展示结果，历史记录不随当前参数变化而重算。

映射登记实际文件、原工作表名、输入/结果列、表头特征、记录区、样式来源、行组规则及来源位置。保留工作表名末尾空格等实际特征；根据真实记录区分配新行，不能仅凭最大行号追加。同批号复测或再次送检不作为重复提交误删。

### 4.3 原表兼容与可靠回写

先验证能够保留字体、边框、列宽、合并、打印设置、目录链接、形状按钮、条件格式及共享公式的读写方式。现成库若通过完整副本验收即可使用；若整本保存会损失形状等对象，则对已纳管模板作 XLSX/OOXML 局部更新，保留无关文件部件。工具选择以验收结果确定，不预先开发通用 Excel 编辑器。

已纳管的结果公式、缓存值和依赖输出同步更新，不依赖某个人打开 Excel 后才出现结果。未验证的联动公式不得上线自动写入。共享公式不能盲目复制索引；新增结果行可采用独立公式。

回写最少满足：

- 提交 ID 保证重复点击和重试不会重复追加；一个正式进程串行处理，禁止不同版本同时写同一正式文件。
- 写前核对模板与文件指纹。平台自己的前次回写按版本链继续处理；外部改值、插行或排序进入冲突核查。
- 写前备份，先更新临时文件并校验，再在同目录原子替换。任务记录前后指纹、定位、备份及状态。
- 文件被 Excel/WPS 锁定时保留任务并提示关闭后重试，不强制覆盖。未锁定的软件也可能稍后保存旧内容，必须配合纳管区域的单一写入规则。
- 进程中断后根据任务和文件指纹判断是否已写入，不能简单重新追加。修订保留版本，不按旧行号盲写。
- 所有纳管模板都要分别在 Excel 和 WPS 中打开、重算、保存，并验证两者相继保存后仍可继续回写。

## 6. 验证、发布与回退

### 6.1 实施顺序

| 阶段 | 优先完成内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：方法与回写验证 | D006/Q 作为候选，核定算法；Excel/WPS 副本回写与布局保留 | 至少覆盖普通滴定、仪器结果、稀释/氟离子和干燥失重的端到端验证 |
| B：内网多人试用 | 浏览器录入、PostgreSQL、权限、回写状态、重复提交及占用处理 | 多人提交不丢记录、不重复写；开发/测试不能写正式数据 |
| C：扩展全项目 | 注册全部工作簿，逐方法核定映射、导入历史并扩展录入 | 已上线方法都有核定样例和 Excel/WPS 兼容证据 |
| D：正式发布 | 固定版本目录、启动管理、备份恢复与切换演练 | 核定范围验收通过，单一正式回写进程与受控文件路径落实 |

两个项目是验证起点，最终覆盖全部 12 个项目；不能用试点成功代替全方法验收。v1 的首个可靠试用版 5–8 周粗估仍作为参考，实际按方法核定、环境与试用反馈调整，全部方法覆盖另核定。

### 6.2 必须通过的检查

1. 计算：正常输入、缺项、零质量、单位换算、稀释、温度修正、平行测定及舍入边界符合核定方法。
2. 文件：允许区域之外的内容保留，按钮、合并、条件格式和打印可用；Excel/WPS 重算与平台结果在核定精度内一致。
3. 并发：两人同文件提交、重复请求、占用、外部插行/排序/改值及进程中断均能正确处理。
4. 历史：示例行不当真实样品，重复导入不重复记录，日期与文件名月份冲突能定位，相同批号的复测可区分。
5. 隔离：开发/测试账号不能访问正式数据库或写正式原表；新版本试运行不能启动第二个正式写入进程。
6. 恢复：在测试环境恢复数据库及对应文件备份，核对回写任务与文件状态，不只验证备份文件存在。

### 6.3 一次发布的最小步骤

1. 确定应用标签和候选发布目录，用独立虚拟环境安装该版固定依赖；在测试数据库与工作簿副本上验收。
2. 进入短暂维护窗口，停止接受新提交，让旧回写任务处理完成；仍有占用/冲突任务时保留并核定新版本的处理兼容性。
3. 停止旧回写进程，备份数据库、工作文件和任务状态；执行已验证的数据库迁移。
4. 启动固定发布目录中的新网页服务和唯一正式回写进程，检查队列、权限和基本查询后开放提交。
5. 记录版本、迁移和验证结果，保留上一版本代码与依赖环境。

回退优先回退兼容的应用代码，不把业务数据直接恢复到旧时点。若有不兼容数据库迁移或新版本已回写文件，必须停写并核对数据库、任务和 Excel 的一致性后恢复；不能只把 Git 切回旧提交就继续写。首期不做自动蓝绿发布或自动数据库降级。
