# v0.0.1 Windows 修订 r2 与本机访问说明

2026-10-09，本机正式服务运行在 `C:\APP\Labwork`。访问地址为 **https://172.28.10.177:8443**，使用安装时设置的账号和密码登录。Windows“服务”中的“理化检测平台”（服务名 `Labwork`）为运行状态；这是后台网页服务，没有托盘图标。

## 访问与证书

服务器本机和 `172.28.10.0/24` 网段内的电脑使用同一个地址。服务器以太网当前为 `172.28.10.177/24`；建议通过固定地址或 DHCP 保留使其不变。其他网段尚未开放。

首次浏览器访问若提示证书不受信任，请导入本机生成的公开根证书 `C:\labwork\tmp\Labwork-root.crt`：双击证书，选择“安装证书”，选择“当前用户”，手动指定“受信任的根证书颁发机构”，完成后重新打开浏览器。其他实验室电脑只需分发这个 `.crt` 文件并导入，勿复制私钥或整个证书目录。

根证书 SHA256 指纹（DER）：`3f737e80f8888feadd48be89ccbadbe3d30f4a474e7cb36e712b211971b3abfa`。此证书属于当前服务器实例，其他安装实例有自己的根证书。

## 修复与版本隔离

安装时填写的 `0.0.0.0` 是监听地址，不是客户端应使用的服务器地址。已备份并修正 `PUBLIC_URL`、允许主机、CSRF 来源、Caddy 地址；保留原网络配置并添加实际网段 `172.28.10.0/24`。防火墙规则 `Labwork-LAN-HTTPS` 仅允许本机 `172.28.10.177` 的 TCP 8443，远端限定上述网段。原配置备份在 `C:\ProgramData\Labwork\backups\access-config-20261009-132346-5ecc2c`，没有修改数据库和账号。

同时发现 WinSW v2.12.0 使用停止参数时必须采用 `<startarguments>`，原配置使用 `<arguments>`，导致系统服务停留在“正在停止”。已修正生成服务 XML 的代码以及本机 XML；本机原 XML 备份为 `C:\APP\Labwork\LabworkService.xml.before-startarguments`。此次通过平台已有的 `stop.request` 正常停止信号解除旧实例等待后重启，没有强制终止数据库。依据：[WinSW v2.12.0 配置文档](https://github.com/winsw/winsw/blob/v2.12.0/doc/xmlConfigFile.md#stopargumentstopexecutable)。

r2 包含 r1 管理员初始化权限修复，新增服务启动参数修复，并在中文安装页和初始化入口拒绝 `0.0.0.0`。程序与数据库结构仍为 v0.0.1/schema 1；源码继续隔离在 `fix/windows-initialize`，发布标签为 `v0.0.1-win-r2`。r1 与原版包、标签均保留。Docker 未改变，继续使用原 v0.0.1 包。
