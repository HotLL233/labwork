# 理化检测平台 v0.0.1 安装与维护

这是局域网网页服务的首个试用版本。客户端使用浏览器；Windows 安装包安装在一台常开服务器上，Docker 包提供另一种服务器部署方式。两种部署不要同时向同一目录回写。

## 1. 版本与业务范围

已实现：账号与项目授权、录入及双次平行测定、服务端计算、草稿、提交、串行 Excel 回写、备份、占用重试、外部修改冲突检测、历史筛选、独立复核、追加修订、工作簿上传/浏览/下载、方法核定与参数快照。

12 个项目提供统一目录；自动计算与回写先支持 D006/Q 的已识别布局：水分、加水稀释水分、氮/氨/有效氯/氯/氢滴定、两次质量稀释氟离子、干燥失重、熔点。其他项目可导入并浏览工作簿，尚未实现其全部方法和历史结构化导入。

初始 D006/Q 是自动生成的空白**试用样表**，没有真实历史数据。候选参数不代表业务核定。上传真实工作簿保留独立副本；先在方法页面核对算法、参数、单位、映射和依据，完成 Excel/WPS 副本验收后再用于正式检测。此次开发没有修改桌面/网盘原件。

## 2. Windows 安装

要求：Windows 10/11 或对应受支持的 Windows Server，64 位；管理员安装，建议预留 3 GB 以上空间，另预留业务数据与备份空间。端口默认 HTTPS 8443、内部网页 18801、PostgreSQL 15432。数据库和内部网页仅监听本机；先检查端口没有被占用。无须另装 Python/PostgreSQL。

1. 在固定服务主机运行 `Labwork-0.0.1-Windows-x64-Setup.exe`，安装页面为简体中文。
2. 设置该主机固定 IPv4/内网域名、HTTPS 端口、允许的实验室网段 CIDR（例如 `192.168.1.0/24`）、管理员用户名和至少 12 位密码。服务器地址不能填写客户端电脑地址。`localhost` 仅用于本机验证。
3. 安装完成后通过 Windows“服务”查看**理化检测平台**（服务名 `Labwork`）。日志在 `C:\ProgramData\Labwork\logs`；初始化错误查看 `setup.log`。
4. 为该 HTTPS 端口建立仅允许实验室网段的入站防火墙规则，例如以管理员 PowerShell 执行：

```powershell
New-NetFirewallRule -DisplayName 'Labwork 内网 HTTPS' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443 -RemoteAddress 192.168.1.0/24 -Profile Domain,Private
```

5. HTTPS 使用 Caddy 内部证书。根证书在 `C:\ProgramData\Labwork\certificates\caddy\pki\authorities\local\root.crt`。由实验室管理员核对 SHA256 指纹后通过组织管理方式分发到客户端可信根证书库；**不要分发同目录的私钥或整个 certificates 目录**。安装包不会修改客户端证书库。
6. 浏览器访问 `https://服务器地址:8443`，登录后先操作试用样表。不要通过忽略证书错误开始正式录入。

程序默认位于 `C:\Program Files\Labwork\releases\0.0.1`，每版独立 Python 与依赖。运行数据位于 `C:\ProgramData\Labwork`；目录权限仅授予管理员、SYSTEM 和 LocalService。配置包含数据库凭据，只给维护人员访问；管理员明文初始密码在初始化成功后删除，数据库仅保存密码散列。

安装与升级保留已有账号、配置、数据库及工作簿，不自动改变地址或方法。卸载停止并注销服务，**保留程序版本和业务数据**，供恢复或重新安装。首次初始化失败且发现孤立数据库时程序拒绝覆盖，需维护人员核查日志后处理，不能反复删除数据尝试。

## 3. Docker 离线部署

要求 Docker Engine / Docker Desktop Linux 容器模式、Docker Compose v2、x86_64。解压 `Labwork-0.0.1-Docker-x64.zip` 后进入目录。包含应用、PostgreSQL、Caddy、Python 镜像，导入后不需要下载镜像。配置和文件使用 Docker 命名卷，不依赖 Windows 目录文件共享。

```powershell
docker load -i images.tar
docker run --name labwork-setup -it -v labwork_runtime:/runtime labwork:0.0.1 python /app/packaging/docker/setup.py
docker cp labwork-setup:/runtime/.env ./.env
docker rm labwork-setup
docker compose up -d
docker compose ps
docker compose logs --tail 100 initialize web worker gateway
```

Windows/Linux 使用相同初始化命令。配置脚本交互输入主机地址、端口、绑定本机内网 IPv4、允许局域网、Docker 私有网段和管理员密码；没有默认密码。避免 Docker 网段与现有网络冲突。配置只生成一次，后续升级保留 `.env` 和命名卷；管理员初始密码在初始化完成后从卷内配置删除。配置文件为 runtime 卷中的 `config.json`，主机 `.env` 包含数据库凭据，须限制访问。

HTTPS 只绑定所选主机内网 IPv4；域名部署须另填该主机实际内网 IPv4。Docker Desktop 可能将客户端地址转换为 Docker 网关地址，程序允许该固定网关来源以便访问；实验室网段边界同时由主机入站防火墙控制，请按 Windows 部分配置允许范围。Linux 部署同样在宿主机/上游防火墙限制内网访问。不能仅用容器中的来源 IP 替代宿主机防火墙。

只公开 HTTPS 端口。数据库、内部网页、工作簿都在容器私有网络与持久卷中。回写文件通过平台上传成为服务器副本；该包不默认挂载 Windows 网盘原路径。

导出根证书：

```powershell
docker compose cp gateway:/data/caddy/pki/authorities/local/root.crt ./labwork-root.crt
```

按 Windows 部分的证书分发要求核对并部署。勿执行 `docker compose down -v`，该命令会删除业务数据。普通停机使用 `docker compose down`，保留命名卷。初始化服务负责显式迁移，网页启动不自动迁移数据库。

## 4. 日常操作与权限

管理员进入“用户与授权”：创建用户、设置初始密码，在项目中添加授权人员。普通授权成员可录入及查询本项目；复核人员加入“复核人员”组后，可复核本人以外的已提交记录。“只读人员”组只能查询和下载，不能提交、修订或复核。管理员可导入工作簿和核定方法。请勿把所有检测人员设为超级用户。

“计算并保存草稿”保存原始数据和计算结果。“计算、提交并写表”另外创建回写任务；只有任务显示“已成功”才说明文件已同步。等待状态可刷新详情查看。文件占用时关闭 Excel/WPS；内容冲突不能直接覆盖，需核对外部改动、待回写任务，并重新登记核定后的文件。

方法变更生成新版本；提交记录保留当时参数和结果。修订创建关联的新记录并追加新行，旧记录不覆盖。下载工作簿是副本，其离线修改不会自动合并回来。初版每条记录支持两次测定，不提供通用在线 Office 编辑或设备实时采集。

## 5. 备份、回退与恢复

源码开发隔离在 `release/v0.0.1` 分支及 `C:\labwork\.worktrees\v0.0.1`，方案基线 `main` 保持独立。发布标签为 `v0.0.1`，不能把 `plan/v1`、`plan/v2` 当成可运行应用回退。

Windows 一致性备份（管理员 PowerShell；先停止接收新提交，停止服务）：

```powershell
$release = 'C:\Program Files\Labwork\releases\0.0.1'
$data = 'C:\ProgramData\Labwork'
Stop-Service Labwork
& "$release\python\python.exe" "$release\app\packaging\windows\control.py" backup --home $data
Start-Service Labwork
```

备份保存在运行目录 `snapshots\时间`，包含 PostgreSQL 自定义格式导出、工作文件、写前备份、配置及结构标记。复制到另一受控磁盘；备份包含凭据与业务数据，限制访问。创建备份时不接受网页提交，数据库导出与文件保持同一时间点。

Docker 一致性备份可在 Windows 使用随包 `backup.ps1`；会停止网页/回写/网关，导出数据库、运行目录（含配置）后重新启动。Linux 按相同步骤执行：停止 gateway/web/worker，数据库 `pg_dump -Fc`，复制 runtime 命名卷以及主机 `.env`，完成后启动服务。不要只备份 Excel。

兼容代码回退示例：停服务、完成备份，确认旧版本目录保留且其 `release.json` 的 schema 与当前相同（本版 schema=1、PostgreSQL=17），再执行维护命令：

```powershell
& "$release\python\python.exe" "$release\app\packaging\windows\control.py" rollback --home $data --version '0.0.1'
Start-Service Labwork
```

实际切换版本保存在 `active.json`，网页/回写/数据库程序读取同一个版本目录。首版没有更早的应用版本可退；上述命令可检查重新选择本版的流程。不得直接恢复旧 Excel 并保留新数据库，或将不兼容数据库自动降级。Docker 回退切换 compose 中应用 image 到已保留且结构兼容的版本，保留同一批业务卷。

数据灾难恢复必须在**隔离目录/数据库**演练：新建同 PostgreSQL 主版本数据库，使用 `pg_restore --no-owner` 恢复 `database.dump`，同时恢复该快照的 workbooks/backups/schema；使用新的测试配置连接恢复库（名称必须 `labwork_test...`）并把回写目录指向恢复副本。核对记录数、任务状态及文件指纹、登录、计算、继续回写后，才安排正式停机恢复。不要将测试配置指向正式网盘目录。

## 6. 试用验收与边界

运行检查见 `v0.0.1-验证记录.md`。开发已检查真实原表副本的局部 XML 回写和无关部件保留；仍须业务人员使用实验室实际 Excel/WPS 版本打开、重算、保存，再确认能继续回写。自动文件验证不能替代这项办公软件验收。真实方法尚未由实验室核定，不应把本版直接当作全部项目的正式上线。

安装包未进行商业代码签名；包内提供第三方许可和组件清单。发布目录提供 SHA256 校验文件。安装包 `/TESTMODE` 只提取程序，不初始化数据、不注册服务，供隔离验证；不是正式安装参数。
